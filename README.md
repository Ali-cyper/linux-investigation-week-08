# Week 08 — Linux Investigation Lab (auth.log · syslog · SSH · Processes · Persistence + PCAP)

Part of a self-designed 12-week SOC investigation curriculum. Earlier weeks covered Windows event logs, PCAP analysis, SIEM correlation and privilege abuse. Week 8 applies the same evidence-first method to Linux: reading authentication logs and syslog, investigating SSH activity, process trees, persistence mechanisms and suspicious commands, plus one light PCAP exercise tied back to host evidence.

> The goal is not to become a Linux system administrator. The goal is to investigate Linux-based activity, correlate events, and produce a defensible SOC verdict.

## Method and rules

- Work each case alone for 30–45 minutes before asking for hints.
- No answer key before submitting my own analysis.
- Every case ends with a SOC report: Verdict (TP / FP / Undetermined), Confidence, Impact, Evidence Ranking, Benign Explanation, Missing Evidence, What Would Change My Mind, SIEM Notes review, Recommended Action, and an English Executive Summary (3–5 sentences).
- Confidence and Impact are separate: high confidence in a verdict does not mean confirmed impact.
- Attempt is not success. A failed login is not a compromise. A command name alone does not prove intent. Absence of evidence is not evidence of absence.
- Depth over speed, evidence over assumptions.

## What this week built, and what is still weak

- **Built:** SIEM Notes review (what each note explains and does not explain), reading process trees by PID/PPID, comparing activity to a baseline, using Undetermined when the evidence cannot decide, spotting beaconing patterns in network data.
- **Still weak:** Evidence Ranking, complete and consistent report submissions, unsupported claims, English report writing, Impact wording. Full list in [`mistake-log.md`](mistake-log.md).
